# Особиста збірка без збереження вмісту запитів

Це модифікований Sub2API для особистого використання. Політика примусово вмикається в `cmd/server` до запуску сервера. Налаштування, база даних і змінні середовища не можуть її вимкнути. Для оновлення потрібно зібрати новий образ із цього форку та знову перевірити зміни.

## Що змінено

- Вбудовані сторінки не отримують токен сесії, ID користувача чи URL поточної сторінки. Вилучаються також старі параметри токенів із налаштованих URL; iframe має sandbox і `no-referrer`. Довільний HTML головної сторінки очищається DOMPurify.
- Аудит промптів і зовнішня модерація заблоковані на рівні HTTP, сервісів та сховищ. Воркери аудиту не стартують; endpoint перевірки зовнішніх сканерів недоступний. Розділи аудиту вилучені з навігації та маршрутизатора інтерфейсу.
- Записи помилок, системні й адміністративні журнали не записуються в БД. Runtime-логер не виводить довільний текст у файли чи stdout; стандартні Go log/slog також спрямовані в цей логер. Обробник HTTP panic не друкує запит.
- Текст reasoning не читається і не пишеться в Redis. Буфер перед початком streaming залишається тільки в RAM (ліміт 8 MiB), без тимчасового файлу.
- Текст відповідей запланованих тестів не записується. Діагностика стану акаунтів і моніторингу зберігає лише загальні позначки, без тексту провайдера.
- Вимкнені плагіни, зовнішня емуляція вебпошуку, S3-збереження зображень, асинхронні та пакетні завдання зображень. Вони могли передавати вміст додатковим одержувачам або потребують його збереження.
- Вбудоване оновлення/відкат заблоковані, щоб випадково не встановити офіційний бінарник без цих змін.

Залишаються облікові записи, їхні ключі/OAuth-токени, налаштування та технічна статистика: модель, кількість токенів, час, вартість, ідентифікатори запитів/акаунтів; де передбачено upstream, також IP і User-Agent. Це не режим повної анонімності або відсутності будь-яких записів. Ключі потрібні сервісу для входу до провайдера, тому захищайте базу даних і доступ адміністратора.

## Що втрачається

Немає детальних журналів для діагностики, локального аудиту/модерації, плагінів, історії фонових зображень та зовнішнього пошукового кешу. Клієнти, які покладаються на відновлення reasoning із Redis під час перетворення Responses → Chat Completions, повинні самі передавати потрібний контекст. Звичайні синхронні GPT-запити та streaming не вимкнені. Власні інструменти пошуку провайдера можуть звертатися до інтернету за його правилами.

## Coolify / Docker Compose

1. Використовуйте Git-репозиторій цього форку, тип Docker Compose, файл `deploy/docker-compose.personal.yml` (контекст збірки — корінь репозиторію).
2. Задайте секрети в Coolify: `POSTGRES_PASSWORD`, `REDIS_PASSWORD`, `ADMIN_EMAIL`, `ADMIN_PASSWORD`, `JWT_SECRET`, `TOTP_ENCRYPTION_KEY`. Для останніх двох згенеруйте **окремі** значення `openssl rand -hex 32`. Не комітьте секрети.
3. Призначте сервісу `sub2api` HTTPS-домен і внутрішній порт **8080**. PostgreSQL/Redis доступні лише у внутрішній мережі. Прив'язка портів до VPS навмисно відсутня.
4. Запускайте зі свіжими томами. Старі БД, Redis, Docker-логи й резервні копії ця зміна не стирає і не очищає. Якщо стара версія вже працювала з реальними запитами, їх потрібно окремо перевірити/видалити після збереження потрібних ключів і налаштувань.
5. Не вмикайте публічну реєстрацію. Увімкніть 2FA адміністратора. Для GPT дозволені upstream-хости `api.openai.com`, `chatgpt.com`, `auth.openai.com`; сторонні relay/proxy або інші моделі потребують окремого рішення.
6. На VPS вимкніть swap/hibernation, якщо потрібна відсутність вмісту RAM на диску. Не підключайте APM, запис HTTP-body або debug-проксі. Перевірте Coolify/Traefik і зовнішній CDN: цей репозиторій не керує їхніми журналами. `tmpfs` може потрапити у swap, якщо він увімкнений.

Compose вимикає Redis RDB/AOF та Docker logging, використовує tmpfs для тимчасових файлів і забороняє core dumps. Ключі й налаштування в PostgreSQL та `/app/data` залишаються постійними. Не використовуйте `weishaw/sub2api:latest`: у ньому немає цих змін. Окремий Compose не був розгорнутий на VPS у межах цієї роботи.

## Межі

Запит і відповідь неминуче обробляються в RAM та надсилаються обраному провайдеру моделі. Політика цього форку не змінює збереження даних на боці OpenAI/іншого провайдера, налаштування клієнта або інфраструктури VPS. Не можна чесно гарантувати «ніде у світі не зберігається» лише зміною проксі. Перевірки використовують синтетичні дані; повний end-to-end тест із вашим акаунтом і Coolify ще потрібен після розгортання.

## Перевірки

```sh
cd backend
go test ./cmd/server ./internal/config ./internal/securityaudit ./internal/service ./internal/repository ./internal/server/middleware ./internal/pkg/logger -run '^TestPersonalPrivacy$'
cd ../frontend
pnpm exec vitest run src/utils/__tests__/embedded-url.spec.ts
pnpm run build
```

Тести політики запускаються в окремих процесах: примусову політику не можна вимкнути назад, а звичайні upstream-тести компонентів повинні лишатися незалежними. Окремий тест `cmd/server` перевіряє, що реальний сервер завжди вмикає політику.
